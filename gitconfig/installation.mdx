J-MaFf's gitconfig installer is a single command per platform. It clones the repository once, runs the setup script, and from that point forward the system maintains itself automatically at each login. The steps below walk you through the prerequisites and the exact command to run on your platform.

## Prerequisites

Before you run the installer, make sure the following are present on your machine:

- **Git** — used to clone the repository and by the aliases themselves.
- **Python 3** — required by the alias helper script. Install from [python.org](https://www.python.org/downloads/) or via your system package manager.
- **pip** — comes with Python 3.4\+. Used to install the `rich` package (required) and `textual` (optional).
- **`rich` Python package** — required for alias tables. The installer installs this automatically; see below if it fails.
- **`textual` Python package** — optional. Powers the interactive `git alias` TUI browser. Without it, `git alias` falls back to a static grouped table.

<Note>
  On Windows, the installer requires **Administrator privileges** to create symlinks and register the scheduled task. The script detects non-elevated sessions and relaunches itself elevated automatically — you will see a UAC prompt.
</Note>

## Clone the Repository

Clone the gitconfig repository to the same location on every machine so the auto-update job always finds it. The recommended location is `~/Scripts/gitconfig` (`$HOME\Scripts\gitconfig` on Windows). Keep it outside `~/Documents`: cloud-backup clients that sync `~/Documents` also sync the `.git` folders inside it, and their conflict copies can break `git fetch`.

```bash
git clone https://github.com/J-MaFf/gitconfig.git ~/Scripts/gitconfig
cd ~/Scripts/gitconfig
```

## Run the Installer

<Tabs>
  <Tab title="macOS">
    ```bash
    bash scripts/mac\ version/install.sh --force
    ```

    The macOS installer:

    - Generates `~/.gitconfig` from the template with the correct repository path substituted.
    - Creates symlinks for `~/.gitignore_global` and `~/gitconfig_helper.py`.
    - Generates `~/.gitconfig.local` with machine-specific defaults: an SSH signing key and `commit.gpgsign` when available, `core.editor` (when VS Code is present and the session isn't SSH/headless), and `safe.directory` entries for this clone plus anything listed in `~/.config/gitconfig/safe-directories`.
    - Installs `rich` and `textual` via pip.
    - Registers a launchd login agent that runs `git selfupdate` at each login.
    - Adds the `Ctrl-G` alias browser keybinding to your `~/.bashrc` or `~/.zshrc`.

    **Optional — SSH commit signing with 1Password:**

    ```bash
    brew install 1password-cli
    bash scripts/mac\ version/install.sh --force
    ```
  </Tab>
  <Tab title="Linux">
    ```bash
    bash scripts/linux\ version/install.sh --force
    ```

    The Linux installer performs the same steps as macOS, but for the auto-sync job it registers a **systemd user timer** (`~/.config/systemd/user/gitconfig-update.{service,timer}`, daily, `Persistent=true`) whenever `systemctl --user` reaches a running user manager. In containers, WSL without systemd, or when there's no user session, it falls back to a daily cron job instead — installing one removes the other. A user timer only runs while you're logged in unless linger is enabled; on a headless machine, run `loginctl enable-linger $USER`.
  </Tab>
  <Tab title="Windows">
    Open PowerShell **as Administrator** (the script will auto-elevate if you forget), then run:

    ```powershell
    & ".\scripts\windows version\install.ps1" -Force
    ```

    The Windows installer:

    - Checks for a Python interpreter right after elevation, before touching any files. If none is found it warns and asks `Continue anyway? (y/n)` — Python only powers the `git alias` browser, so the core install still works without it. `-Force` answers yes automatically.
    - Generates `~/.gitconfig` from the template.
    - Creates symlinks for `~/.gitignore_global` and `~/gitconfig_helper.py` (requires Admin).
    - Generates `~/.gitconfig.local`.
    - Installs `rich` and `textual` via pip.
    - Registers a **Task Scheduler** task named `GitConfig Pull at Login` that fires at login.
    - Adds the `Ctrl-G` alias browser keybinding to your PowerShell profile (`$PROFILE.CurrentUserAllHosts`).

    **Skip the scheduled task:**

    ```powershell
    & ".\scripts\windows version\install.ps1" -Force -NoTask
    ```
  </Tab>
</Tabs>

<Note>
  `scripts/mac version/install.sh` and `scripts/linux version/install.sh` are now thin wrappers around a single shared implementation, `scripts/unix/install.sh` — the commands above are unchanged, but you can also call the unified script directly.
</Note>

## Setup Flags

The macOS/Linux and Windows installers expose matching flags for granular control.

**macOS and Linux** (`scripts/unix/install.sh`, or the `mac version`/`linux version` wrappers):

| Flag | Effect |
| --- | --- |
| `-f`, `--force` | Overwrite existing files without prompting. Use this for fresh installs and re-installs. |
| `--reinstall` | Tear down the previous install first (runs `cleanup-gitconfig.sh --force`; removed files are still backed up) before reinstalling. |
| `--no-scheduler` | Skip the auto-sync job (the launchd agent on macOS, the systemd user timer or cron job on Linux). `--no-launchd` and `--no-cron` are accepted as synonyms. |
| `-h`, `--help` | Print the full usage summary and exit. |

**Windows** (`scripts/windows version/install.ps1`):

| Flag | Effect |
| --- | --- |
| `-Force` | Overwrite existing files without prompting. Use this for fresh installs and re-installs. Also answers "yes" to the Python preflight prompt automatically. |
| `-NoTask` | Skip Task Scheduler registration. Use this on machines where you don't want auto-sync. Without `-Reinstall`, this no longer removes an existing login task from a previous install. |
| `-Reinstall` | Tear down the existing install first (`Cleanup-GitConfig.ps1 -Force -KeepLocal`, which also removes the scheduled task) before reinstalling. |
| `-Help` | Print the full usage summary and exit. |

<Note>
  A plain re-run (no `--reinstall`/`-Reinstall`) now converges in place instead of tearing everything down first: existing files that differ are backed up and regenerated, and links that already point into the repo are left alone. Full cleanup only runs when you explicitly pass `--reinstall` or `-Reinstall`.
</Note>

<Note>
  On macOS/Linux, the installer and `cleanup-gitconfig.sh` exit `1` on a step failure. On an unattended run (no terminal attached to answer a prompt), a missing answer counts as "no" rather than hanging. On Windows, `install.ps1` reports step failures explicitly instead of continuing silently, and keeps your existing files intact if the install or a cleanup fails partway through.
</Note>

You can also run the individual sub-scripts directly:

```powershell
# Regenerate ~/.gitconfig from the template only
& ".\scripts\windows version\Initialize-GitConfig.ps1" -Force

# Recreate symlinks only
& ".\scripts\windows version\Initialize-Symlinks.ps1" -Force

# Regenerate ~/.gitconfig.local only
& ".\scripts\windows version\Initialize-LocalConfig.ps1" -Force
```

## What the Installer Creates

After a successful run you will have:

| File | Description |
| --- | --- |
| `~/.gitconfig` | Generated from the template. **Do not edit directly** — changes will be overwritten on the next `git selfupdate`. |
| `~/.gitconfig.local` | Machine-specific overrides. Included by `~/.gitconfig` via `[include]`. **Safe to edit freely.** |
| `~/.gitignore_global` | Global ignore patterns for IDEs, OS files, and build artifacts. |
| `~/gitconfig_helper.py` | Python helper invoked by aliases like `git alias`, `git cleanup`, and `git main`. |

## Machine-Specific Configuration

Open `~/.gitconfig.local` at any time with:

```bash
git localconfig
```

Put any setting that should only apply to this machine in that file — a different signing key, a work email address, or `safe.directory` entries for mounted paths. The auto-update job never touches it, but **regenerating it (`install.sh --force`, or `Initialize-LocalConfig.ps1 -Force` on Windows) now preserves what you added** — your own entries land in a "Your settings" section — while rebuilding only the signing, credential-helper, and `core.excludesfile` settings, printing the names of any that changed.

To trust additional paths beyond this clone (a network share, a repo owned by another account) as `safe.directory`, list them in `~/.config/gitconfig/safe-directories` — one path per line, blank lines and `#` comments are skipped — then regenerate `~/.gitconfig.local` as above. On Windows, write UNC paths in git's `%(prefix)///server/share/repo` form.

## Auto-Update Job

<Note>
  The auto-update job runs at every login. It performs `git pull` on the gitconfig repository, and if `.gitconfig.template` changed in that pull, regenerates `~/.gitconfig` automatically. It also prunes merged branches in the repository to keep things tidy. Run the same operation on demand at any time with `git selfupdate`.
</Note>

Before any generated or linked file is replaced, the previous version is saved as a timestamped backup (`<file>.bak.YYYYMMDD-HHMMSS`), keeping the newest 5 backups per file. Set the `GITCONFIG_BACKUP_KEEP` environment variable to change that limit — `0` keeps all of them. A symlink that already points into the repo is left alone; a stale one is replaced without a backup, so re-running never creates new backups for it.

Your original pre-install file is also kept permanently: the first time a file is backed up, a copy is saved as `<file>.pre-gitconfig` (for example `~/.gitconfig.pre-gitconfig`). That copy is never pruned or overwritten by the 5-backup rotation above, so you can always recover the file you had before installing. (On an install from before this copy existed, the oldest surviving timestamped backup is used instead.)

## Verifying the Installation

Run a quick sanity check after install:

```bash
git alias --plain   # Should print a grouped table of all aliases
git s               # Should show your working-tree status (short form)
git selfupdate      # Should pull the repo and report "Already up to date" or apply changes
```

If `git alias` prints an error about Python not being found, install Python 3 and re-run the installer. If `rich` is missing, install it manually:

```bash
python -m pip install rich textual
```
