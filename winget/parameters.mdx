`winget-app-install.ps1` accepts three optional switches. Running the script with no arguments performs a standard unattended install — the script never asks a yes/no question, so there are no update or scheduling parameters to configure. Ongoing updates are handled by [Winget-AutoUpdate](/winget/scheduled-updates), which the installer sets up automatically.

<Note>
  Older versions accepted `-CheckForUpdates`, `-AutoInstallUpdates`, `-EnableScheduledUpdates`, `-DisableScheduledUpdates`, and `-UpdateFrequency`. These were removed along with the homegrown updater when updates moved to Winget-AutoUpdate. If you have automation passing these flags, drop them — the script no longer recognises them.
</Note>

## Parameters

<ParamField query="WhatIf" type="Switch">
  Performs all pre-flight checks and prints every action the script *would* take, but makes no changes to the system. No apps are installed, no configuration is written, and Winget-AutoUpdate is not set up. If PowerShell 7 is not present, a `-WhatIf` run previews the bootstrap without installing anything.

  Use this flag to validate the script's behaviour in a new environment before committing to a full run. Dry-run transcripts get a `-whatif` suffix in the log filename.

  ```powershell
  .\winget-app-install.ps1 -WhatIf
  ```
</ParamField>

<ParamField query="SkipSystemCheck" type="Switch">
  Bypasses the pre-flight validation of OS version, available disk space, and network connectivity. Useful for headless or automated deployments where you have already confirmed requirements externally. The switch is forwarded across the elevation relaunch and the PowerShell 7 bootstrap.

  ```powershell
  .\winget-app-install.ps1 -SkipSystemCheck
  ```
</ParamField>

<ParamField query="NonInteractive" type="Switch">
  Suppresses the two interactive-only extras: the summary `Out-GridView` window and the final "press any key to exit". Intended for RMM, CI, and scheduled-task use. Non-interactive mode is also auto-detected when the session is non-interactive or stdin is redirected, so passing the switch is only needed to force it.

  ```powershell
  .\winget-app-install.ps1 -NonInteractive
  ```
</ParamField>

## Parameter combinations

```powershell
# Dry run — preview what would be installed without making any changes
.\winget-app-install.ps1 -WhatIf

# Automated pipeline — skip environment checks, suppress interactive extras
.\winget-app-install.ps1 -SkipSystemCheck -NonInteractive

# Preview in an environment where pre-flight checks are known to fail
.\winget-app-install.ps1 -WhatIf -SkipSystemCheck
```

All three switches are forwarded when the script relaunches itself — for elevation or the PowerShell 7 bootstrap — so the effective behaviour is the same no matter which shell you start from.
