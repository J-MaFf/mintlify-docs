The printer scripts handle the most common printer support scenarios in a Windows environment: letting a standard user connect a branch's shared network printers or the KFI office IPP printers themselves, diagnosing the notorious error 0x0000006ba, and restarting a hung Print Spooler service.

<Warning>
  `Debug-PrintError.ps1` and `Repair-PrintSpooler.ps1` require an **elevated (Administrator) PowerShell session**. `Add-NetworkPrinter.ps1` and `Install-KfiPrinter.ps1` are the opposite by design — they run as a standard user and never elevate, so a driver that would need an admin install is reported, not silently attempted.
</Warning>

---

## Add-NetworkPrinter.ps1

Double-clickable, non-admin installer that lets a standard user pick **Company → Branch**, see that branch's shared printers discovered live from its print server, pick one or more, and connect them with `Add-Printer -ConnectionName`. Nothing is hard-coded per printer — only each branch's print server address lives in the script's built-in catalog (currently `KFI` / `Walworth`).

Each discovered printer is tagged with whether the connection can succeed without admin rights: a v4/class-driver printer connects through the inbox "Microsoft enhanced Point and Print" driver with no install, so a standard user succeeds (`[no admin needed]`); a v3 vendor-driver printer needs that driver already present on the PC (`[driver needed - IT]`) or its version is unknown (`[driver unknown]`) — those are shown and allowed to fail with a clear message rather than hidden.

### Usage

```powershell
# Double-click Add-NetworkPrinter.bat, or run the script directly:
.\Scripts\Printers\Add-NetworkPrinter.ps1

# Shows the Company, Branch, and Printer menus and connects whatever is picked
```

<ParamField path="-Company" type="string">
  Which company's catalog entries to use. Omit to show a numbered menu — skipped automatically when the catalog has exactly one company.
</ParamField>

<ParamField path="-Branch" type="string">
  Which of the company's branches to use. Omit to show a numbered menu — skipped automatically when the company has exactly one branch.
</ParamField>

<ParamField path="-Printer" type="string[]">
  One or more share names (the `ShareName`, not the friendly name) to connect without showing the printer menu. Case-insensitive; each value must match a share discovered live on the branch's print server.
</ParamField>

```powershell
# Skip all three menus for unattended/scripted use
.\Scripts\Printers\Add-NetworkPrinter.ps1 -Company KFI -Branch Walworth -Printer 'CopyRoom-HP', 'Front-Zebra'
```

A transcript of every run is written to `%LOCALAPPDATA%\PrinterInstall\Add-NetworkPrinter_<yyyyMMdd-HHmmss>.log`.

<Note>
  No admin rights needed — the script never checks for, requests, or requires administrator rights. It must run on the branch's own network (or a domain trust that reaches it); the print server isn't reachable otherwise. Exit codes: `0` = every selected printer connected (or the user quit a menu without selecting anything); `1` = at least one printer failed, or the supplied Company/Branch/Printer didn't match.
</Note>

## Install-KfiPrinter.ps1

Installs the KFI01 and/or KFI02 HP MFP M776 printers as direct IPP queues, with no administrator rights and nothing pre-staged by IT. On Windows 11 24H2 or later it calls the WinRT `Windows.Devices.Printers.IppPrintDeviceManager` API — the same one Settings uses — and reports the result automatically. On older Windows (or when that API is unavailable) it falls back to opening Settings at the printers page with the exact numbered steps to follow, then watches the printer list until the new queue appears (or times out after five minutes).

### Usage

```powershell
# Double-click Install-KfiPrinter.bat, or run the script directly:
.\Scripts\Printers\Install-KfiPrinter.ps1

# Shows a menu (1 = KFI01, 2 = KFI02, 3 = both, Q = quit)
```

<ParamField path="-PrinterName" type="string">
  `KFI01`, `KFI02`, or `All` for both. Omit to show the console menu.
</ParamField>

```powershell
# Skip the menu
.\Scripts\Printers\Install-KfiPrinter.ps1 -PrinterName All
```

A transcript of every run is written to `%LOCALAPPDATA%\KfiPrinterInstall\Install-KfiPrinter_<yyyyMMdd-HHmmss>.log`.

<Note>
  No admin rights needed — the script never checks for, requests, or requires administrator rights. The PC must be on the KFI office network (not VPN or guest Wi-Fi). Exit codes: `0` = every selected printer is installed (or was already installed); `2` = no failures, but at least one printer needs the Settings steps finished by hand; `1` = at least one printer failed.
</Note>

## Debug-PrintError.ps1

A comprehensive diagnostic script for the Windows print error **0x0000006ba** ("The print spooler service is not running"). It checks local and remote services, firewall rules, network connectivity, and recent event log entries, then prints a categorized remediation guide.

### Usage

```powershell
# Run without a print server argument to check local state only
.\Scripts\Printers\Debug-PrintError.ps1

# Include a print server to test connectivity and remote spooler status
.\Scripts\Printers\Debug-PrintError.ps1 -PrintServer 'PRINTSERVER01'

# Use an IP address if DNS resolution is the suspected problem
.\Scripts\Printers\Debug-PrintError.ps1 -PrintServer '192.168.1.100'
```

### What the Script Checks

<Steps>
  <Step title="Local services">
    Verifies that the **Print Spooler** (`Spooler`) service and the RPC services (`RpcSs`, `RpcEptMapper`) are running on the local machine.
  </Step>
  <Step title="Print server connectivity">
    When `-PrintServer` is supplied, pings the server and tests TCP ports 135, 445, and 139.
  </Step>
  <Step title="Remote Spooler service">
    Checks whether the Spooler service is running on the remote print server.
  </Step>
  <Step title="Local printer connections">
    Lists all network printer connections and their reported status.
  </Step>
  <Step title="Windows Firewall">
    Checks whether the **File and Printer Sharing** firewall rules are enabled on the local machine.
  </Step>
  <Step title="Event log">
    Searches the System event log for Spooler-related events (IDs 7031, 7032, 7034, 7036) from the past 24 hours.
  </Step>
  <Step title="Remediation guide">
    Prints five categorized fix suggestions: restart services, clear the print queue, check the print server, reset printer connections, and network troubleshooting steps.
  </Step>
</Steps>

Each check is timestamped and color-coded — green `[✓]` for passing, red `[✗]` for failures, yellow `[!]` for warnings, and cyan `[i]` for informational output.

## Repair-PrintSpooler.ps1

A focused script that checks the Print Spooler service status and restarts it if it is stopped or in a failed state. Use this as a quick fix when the spooler has hung without needing to run the full diagnostic.

### Usage

```powershell
# Check and repair the spooler silently
.\Scripts\Printers\Repair-PrintSpooler.ps1

# Show detailed step-by-step output
.\Scripts\Printers\Repair-PrintSpooler.ps1 -Verbose
```

### What the Script Does

```powershell
# Equivalent manual steps the script automates:

# 1. Check current status
Get-Service -Name 'Spooler'

# 2. If not running, stop any intermediate state and restart
Stop-Service -Name 'Spooler' -Force
Start-Service -Name 'Spooler'

# 3. Confirm it is running
Get-Service -Name 'Spooler'
```

The script waits up to 30 seconds for the service to reach the `Stopped` state before restarting, and another 30 seconds for it to reach `Running`. If either timeout is exceeded, it exits with error code `1` and a clear message.

**Exit codes:**

| Code | Meaning |
|---|---|
| `0` | Spooler is running (already was or successfully restarted) |
| `1` | Failed to repair — manual intervention required |

<Tip>
  If `Repair-PrintSpooler.ps1` exits with code `1`, run `Debug-PrintError.ps1` for a full picture of what is blocking the service from starting (driver issues, corrupted spool files, RPC failures, etc.).
</Tip>

### Clearing a Stuck Print Queue

If the spooler restarts but immediately stops again, a corrupted job in the spool folder is often the cause. Clear it manually before restarting:

```powershell
# Stop the spooler, clear the queue, restart
Stop-Service -Name 'Spooler' -Force
Remove-Item -Path 'C:\Windows\System32\spool\PRINTERS\*' -Force -ErrorAction SilentlyContinue
Start-Service -Name 'Spooler'
```
